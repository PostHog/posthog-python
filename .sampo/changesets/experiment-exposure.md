Send `$experiment_exposure` when a remotely evaluated config version 2 flag assigns an experiment variant. The SDK sends it together with `$feature_flag_called`, from `get_feature_flag()`, `feature_enabled()`, `get_feature_flag_result()`, and the `is_enabled()` and `get_flag()` reads of an `evaluate_flags()` snapshot. It carries the flag key, the same `$feature_flag_response` as its `$feature_flag_called`, the variant key and rule ID, `locally_evaluated: false`, and the flag ID, version, request ID and evaluation time when the response has them. It is sent once per distinct ID, groups, flag, rule and variant, whatever value or request it came from. `$feature_flag_called` for a config version 2 flag also gets `$feature_flag_config_version` and `$feature_flag_reason_code`. A targeting match, rollout miss, paused experiment or holdout adds the `$feature_flag_rule_id` and `$feature_flag_rule_type` it names, and a complete experiment split adds these and `$feature_flag_variant`. Other outcomes, including failed flags, add no rule properties. Minimal `$feature_flag_called` events keep these properties, and their dedupe includes them, so equal-valued arms and successive experiments of one flag are each reported. A split that lacks its rule type, rule ID or variant key sends no exposure and reports no rule or variant. A `get_feature_flag_payload()` lookup with `match_value` reports the caller's value, so it sends no exposure. `send_feature_flag_events=False` suppresses both events. Config version 1 flags, locally evaluated flags and `$feature_flag_response` are unchanged.
