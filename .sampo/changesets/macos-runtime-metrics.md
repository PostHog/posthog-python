Add opt-in, dependency-free macOS runtime metrics with `metrics={"capture_runtime_metrics": True}`. Process metrics follow OpenTelemetry conventions: cumulative `process.cpu.time` counters and CPU-normalized `process.cpu.utilization` gauges distinguished by `cpu.mode`, plus current RSS (`process.memory.usage`) and native threads (`process.thread.count`) as cumulative non-monotonic sums. `process.memory.utilization` reports RSS divided by total physical RAM as a gauge fraction, not utilization against a container limit. CPython GC collections, collected objects, and uncollectable objects use cumulative `gc.get_stats()` counters distinguished by `cpython.gc.generation`, not allocation bookkeeping or heap-size measurements.

Retain custom `app.process.cpu.percent` (100% means one busy core) and cumulative `app.process.cpu.ctx_switch.total` (the native reader provides a combined count, not OpenTelemetry's required voluntary/involuntary split). Runtime sums preserve the latest observation and a stable start time across flushes and retries; manual metrics retain their existing wire format and delta aggregation. Forked workers receive independent identities and counter baselines. `shutdown()` collects a final sample, flushes, and stops collection. Unsupported platforms warn and do not collect; collection remains disabled by default.

Separately enable dependency-free macOS host metrics with `capture_host_metrics=True`: aggregate CPU busy fraction, explicitly estimated available memory (free + inactive), native categorical memory pressure, used swap, and page-accounted compressed swap transfer bytes. Only swap usage uses a standard OpenTelemetry instrument; the other host instruments use custom `app.system.*` names. Pressure readings are best-effort and omitted when unavailable. Enable a single collector per host to avoid duplicates; inherited clients do not restart host collection after fork.
