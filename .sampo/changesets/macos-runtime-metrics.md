Add opt-in, dependency-free macOS runtime metrics with `metrics={"capture_runtime_metrics": True}`. Process metrics follow OpenTelemetry conventions: cumulative `process.cpu.time` counters and CPU-normalized `process.cpu.utilization` gauges distinguished by `cpu.mode`, plus current RSS (`process.memory.usage`) and native threads (`process.thread.count`) as cumulative non-monotonic sums. `process.memory.utilization` reports RSS divided by total physical RAM as a gauge fraction, not utilization against a container limit. CPython GC collections, collected objects, and uncollectable objects use cumulative `gc.get_stats()` counters distinguished by `cpython.gc.generation`, not allocation bookkeeping or heap-size measurements.

Also collect custom `app.cpython.gc.duration` delta histograms in milliseconds by generation, using `gc.callbacks`. These measure collection wall time, not exact application pause time. Callbacks only buffer observations; hooks, aggregation, and export run at flush time. The buffer is bounded, and skipped observations produce a bounded warning. Shutdown, collector cleanup, and fork remove the callback without disturbing application callbacks.

Collect standard cumulative `process.context_switches` with native `getrusage()` counts distinguished by `process.context_switch.type=voluntary|involuntary`, independently of libproc reads. Derive per-core-equivalent process CPU percentage with `rate(process.cpu.time) * 100`, summing CPU modes, instead of a separate percentage metric. Automatic process metrics carry `process.pid` and resource-level `service.instance.id` (generated) and `host.name` (the same native hostname used by host collection, unless explicitly configured through `resource_attributes`), not a `process.runtime_id` point attribute. Manual and host metrics retain their configured resource attributes. Runtime sums preserve the latest observation, resource identity, and a stable start time across flushes and retries; manual metrics retain their existing wire format and delta aggregation. Forked workers receive independent identities and counter baselines. `shutdown()` collects a final sample, flushes, and stops collection. Unsupported platforms warn and do not collect; collection remains disabled by default.

Separately enable dependency-free macOS host metrics with `capture_host_metrics=True`: standard `system.cpu.utilization` gauges per logical CPU and mode (`user`, `system`, `idle`, `nice`), `system.memory.usage` non-monotonic sums by state, installed physical RAM as `system.memory.limit`, used swap as `system.paging.usage`, native categorical memory pressure, and page-accounted compressed swap transfer bytes. CPU uses zero-based integer `cpu.logical_number` attributes; exclude idle and sum the remaining modes to chart busy utilization per CPU, then average across CPUs for aggregate busy utilization. Following psutil's macOS accounting, memory `free` excludes speculative pages and `used` is active plus wired pages. Unsupported `cached` and `buffers` states are omitted; these readings are not an available-memory estimate, do not necessarily sum to total RAM, and are not container limits. Native Mach buffers and host ports are released after each read. Initial CPU readings and CPU-topology changes establish fresh baselines; zero-delta CPUs are omitted. Retain custom `app.system.swap.io` because native swap counters measure page-accounted compressed transfer bytes, not operation counts or physical disk traffic. Keep `app.system.memory.pressure` unchanged; readings are best-effort and omitted when unavailable. Enable a single collector per host to avoid duplicates; inherited clients do not restart host collection after fork.
