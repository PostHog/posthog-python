`emails.send` takes an optional `category` on the code form, the one with `template_key`. Leave it out for transactional email with no category, as before, or to follow the category of the eligible template that `template_key` names (when code-send categories are enabled). A matching template made in PostHog must first be enabled for transactional sends (otherwise PostHog refuses it with `template_not_transactional`), and an enabled template in a marketing category is refused with `marketing_template`. A matching sendable template fixes the category: for an uncategorized template, omit `category` or pass `TRANSACTIONAL_CATEGORY` (`"transactional"`); for a categorized transactional template, omit `category` or pass its matching `key` and `type` (passing `TRANSACTIONAL_CATEGORY` there returns `category_mismatch`). Pass a `MessageCategory` with a `key`, a `type` (`"marketing"` or `"transactional"`), a `name` and an optional `description` to file the email under that category: when the project has room under its active category limit, a send creates the category using its name and description when none exists with that key, or restores a deleted one while keeping its existing name and description; any other send leaves the category as it is, so you change its name or description in PostHog. A marketing send honors the recipient's opt-outs, and its HTML body must link `<a href="{{ unsubscribe_url }}">` (or its `text` body must hold `{{ unsubscribe_url }}` when there is no `html`). PostHog refuses a send with the error codes `category_mismatch`, `too_many_categories`, `unsubscribe_link_required`, `copies_not_allowed`, `recipient_opted_out`, `template_not_transactional` and `marketing_template`.
